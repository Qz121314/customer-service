# 坐席消息提醒验收清单

## 产品规则

- Android / iOS：每条新客户消息请求声音和震动；PC：每条新客户消息请求声音。
- 工作台没有静音开关。旧的本机声音、震动关闭偏好不再影响接收；系统通知按钮用于开启或重新确认订阅。
- 文字、图片、商品咨询均使用真实 messageId。新咨询与普通回复保持不同标题及震动节奏。
- 获授权后，前台实时消息和后台 Push 共用 Service Worker 入口，始终请求非静音通知，不因窗口可见或正在聊天而静音。
- 同一消息的重复实时事件去重；每次 Push 都调用 showNotification，以满足 iOS userVisibleOnly 要求，重复 Push 使用同一 tag 和 renotify:false 替换现有通知；成功提交后在设备 IndexedDB 记录消息 ID，保留 24 小时，不保存消息内容。存储不可用时以内存和通知 tag 尽力去重，不能阻止通知。
- 系统接受通知请求不等于设备实际发声、震动；实际结果仍受权限、勿扰、音量、通知渠道、省电和网络影响。
- 系统通知不可用时尝试网页提示音与受支持的网页震动。两项能力分别记录成功，失败不消耗消息；用户操作、恢复可见或网络恢复后只重试失败部分。
- 当前会话增量恢复的新客户消息进入同一提醒入口；历史加载、向前翻页、客服自发消息、自动问候、输入、已读和状态事件不提醒。
- 未打开会话的 Inbox 快照没有每条消息 ID，不凭未读数量伪造提醒；后台遗漏依靠逐消息 Push。此改动不增加 Worker / D1 查询或轮询。
- 网页音色选项用于兜底及测试，系统通知音色由操作系统选择。

## 通用准备

- 同一客服登录 PC、Android、iOS PWA；准备独立访客发送文字、图片和商品咨询。
- 检查功能菜单中的连接、系统通知、后台 Push、提示音和 PWA 状态；确认没有静音按钮。
- 开启系统通知声音与震动，检查勿扰、音量、省电、通知渠道。
- 点击测试提示音；支持网页震动时点击测试震动。失败应显示反馈。

## Android

- 普通支持 Push 的浏览器和安装后的 PWA 分别验证。
- 前台、当前会话、其他会话、后台、锁屏分别收消息，每条请求非静音系统通知及震动。
- 连发三条文字和一张图片，四个真实 ID 分别提醒，不按会话合并。
- 拒绝系统通知权限，页面活跃时走网页兜底。
- 音频失败但震动成功：再次交互只重试声音；震动被拒但声音成功：只重试震动。

## iPhone / iPad

- Safari 普通标签页显示添加到主屏幕指引。
- 添加到主屏幕，从图标启动，再主动授权通知。
- 没有 navigator.vibrate 也必须通过系统通知请求声音和震动；不伪装成支持网页震动。
- 前台、当前会话、切其他 App、锁屏分别验证新咨询、文字和图片。
- 音频中断后返回页面，状态反映真实运行情况；下一次操作可以重试，不能依赖只执行一次的解锁监听。
- 系统权限被拒时只提供可用网页声音与明确提示，不承诺网页震动替代。

## PC

- 系统获授权后，客服页可见、管理页可见、当前会话打开或所有页面在后台，都请求非静音通知。
- 未授权时使用网页提示音；不支持震动时不调用该能力。
- 多标签页同时收到同一消息，随后 Push 到达，同一 ID 的实时事件不重复提交通知，Push 更新同一通知 tag 并设置 renotify:false。
- Service Worker 重启后重送成功 ID，设备记录仍可去重。

## 失败、恢复和升级

- 系统提交拒绝时不写成功记录；同一 ID 再次到达可以重试。
- 当前会话断线后补回新消息，提醒一次；已提醒 ID 不重复。
- Badge 抛错不能阻止通知。
- 老 Service Worker 尚不支持确认协议时，通过相同 tag 的非静音系统通知兜底。
- 点击通知仍直达对应会话；已读、Badge、Logout、重新登录绑定保持原契约。
- 记录真机型号、系统和浏览器版本、权限及实际结果。自动化不能替代真机扬声器和震动验收。
