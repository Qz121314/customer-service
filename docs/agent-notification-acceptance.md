# 坐席消息提醒验收清单

本清单用于验证客服坐席的前台提示音、移动端震动、PWA / Web Push 能力。目标是在平台允许的范围内达到最高实际可靠性，不承诺每条系统 Push 在所有网络和系统状态下 100% 即时到达。

## 固定产品规则

- 每一条成功持久化的客户文字、图片或 `product_context` 消息都必须使用真实 `messageId` 触发一次提醒。
- `NEW_CONVERSATION` 与 `CUSTOMER_REPLY` 使用不同提示音和震动节奏。
- 同一个 `messageId` 因 WebSocket 重连、recovery 或历史补消息再次出现时不得重复提醒。
- 客服自己发送的消息、自动问候、输入状态、已读事件和会话状态事件不得触发客户消息提醒。
- PC 工作台以前台提示音为主；不支持 `navigator.vibrate` 的设备不显示震动控制，也不执行震动。
- 支持振动的移动设备以前台提示音 + 震动为默认组合。
- “消息提示音”和“震动提醒”是当前设备的独立本地偏好，默认开启；一个设备关闭不能修改同一客服其他设备的偏好。
- “客户消息通知”单独控制后台 / 锁屏 Web Push。系统通知的最终声音、震动、投递时间和通知渠道行为由操作系统、浏览器、勿扰模式与省电策略决定。

## 通用准备

- 同一个客服分别登录 Desktop 和待测手机，确认两端保持登录。
- 在坐席“功能菜单”确认实时连接、系统通知、后台 Push、提示音、震动（支持设备）和 PWA 状态。
- 开启系统通知声音，关闭 Focus / 勿扰；检查浏览器或 PWA 未被系统禁止后台通知。
- 准备一个独立访客页面，用于创建会话、连续发送文字和图片。

## 前台提醒与设置

- 首次进入坐席时，“消息提示音”默认开启。
- 支持 `navigator.vibrate` 的移动设备，“震动提醒”默认开启；不支持振动的 PC 不显示该开关。
- 关闭“消息提示音”后，客户前台消息仍正常进入会话、未读和 Badge，但不播放工作台提示音。
- 重新开启“消息提示音”后立即恢复；刷新或重新打开当前设备仍保留该选择。
- 关闭“震动提醒”后，支持设备的前台客户消息不再调用工作台震动；重新开启后恢复并在本机持久化。
- 点击“测试提示音”立即播放一次 `CUSTOMER_REPLY` 提示音，不改变开关状态。
- 点击“测试震动”立即执行一次 `CUSTOMER_REPLY` 震动节奏，不改变开关状态。
- 前台接收一个新会话：会话立即出现，播放更明显的新会话提示音；支持设备且震动开启时执行更明显的新会话震动。
- 前台连续接收三条已有会话回复：三条均出现，每个真实 `messageId` 各提醒一次。
- 模拟 Inbox WebSocket 重连和增量 recovery：已提醒过的 `messageId` 不得再次响铃或震动。
- 客服自己发文字、图片或名片，以及 visitor typing / read receipt / status 更新均不得触发客户消息提醒。

## iPhone / iPad Home Screen PWA

- Safari 分享菜单选择“添加到主屏幕”，必须从桌面图标启动坐席 PWA。
- 主动授予通知权限；若拒绝，确认页面显示后台提醒风险。
- 前台重复“前台提醒与设置”中的每条消息、声音开关和自检场景。
- 切到其他 App 后接收文字与图片：通知中心各出现一次系统通知。
- 锁屏后接收新会话与已有会话回复：标题分别显示“新客户咨询”和“客户回复”。
- 点击任一通知：直接打开其 `conversationId` 对应会话，并补回断线期间消息。
- 打开会话并完成已读：Badge 按未读消息数减少；全部已读后清除。
- Wi-Fi 切换蜂窝网络、离线后恢复在线：恢复后补齐缺失消息且不重复工作台响铃。
- 验证手机 Logout 后 Desktop 仍可收发；Desktop 最后 Logout 后客服变为 offline。

## Android PWA

- 使用支持 Web Push 的浏览器安装 PWA，并授予通知权限。
- 重复 iPhone 清单中的前台、后台、锁屏、连续文字、图片、直达会话与网络恢复场景。
- 确认支持时前台震动：新会话 pattern 比普通客户回复更明显。
- 确认“震动提醒”关闭后前台不震动，重新开启后测试按钮和客户消息均恢复震动。
- 确认后台 / 锁屏声音与震动由系统通知渠道控制。
- 检查 Launcher Badge 或通知点；具体显示数字还是圆点取决于设备 Launcher。
