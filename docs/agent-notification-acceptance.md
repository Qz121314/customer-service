# 坐席移动端消息提醒验收清单

本清单用于真机验证 PWA / Web Push 能力。目标是在平台允许的范围内达到最高实际可靠性，不承诺每条通知在所有网络和系统状态下 100% 即时到达。

## 通用准备

- 同一个客服分别登录 Desktop 和待测手机，确认两端保持登录。
- 在坐席“功能菜单”确认实时连接、系统通知、后台 Push、提示音和 PWA 状态。
- 开启系统通知声音，关闭 Focus / 勿扰；检查浏览器或 PWA 未被系统禁止后台通知。
- 准备一个独立访客页面，用于创建会话、连续发送文字和图片。

## iPhone / iPad Home Screen PWA

- Safari 分享菜单选择“添加到主屏幕”，必须从桌面图标启动坐席 PWA。
- 主动授予通知权限；若拒绝，确认页面显示后台提醒风险。
- 前台接收新会话：会话立即出现，播放更明显的新会话提示音，未读与 Badge 增加。
- 前台连续接收三条已有会话回复：三条均出现，每条各提醒一次，不重复。
- 切到其他 App 后接收文字与图片：通知中心各出现一次系统通知。
- 锁屏后接收新会话与已有会话回复：标题分别显示“新客户咨询”和“客户回复”。
- 点击任一通知：直接打开其 `conversationId` 对应会话，并补回断线期间消息。
- 打开会话并完成已读：Badge 按未读消息数减少；全部已读后清除。
- Wi-Fi 切换蜂窝网络、离线后恢复在线：恢复后补齐缺失消息且不重复响铃。
- 验证手机 Logout 后 Desktop 仍可收发；Desktop 最后 Logout 后客服变为 offline。

## Android PWA

- 使用支持 Web Push 的浏览器安装 PWA，并授予通知权限。
- 重复 iPhone 清单中的前台、后台、锁屏、连续文字、图片、直达会话与网络恢复场景。
- 确认支持时前台震动：新会话 pattern 比普通客户回复更明显。
- 确认后台 / 锁屏声音与震动由系统通知渠道控制。
- 检查 Launcher Badge 或通知点；具体显示数字还是圆点取决于设备 Launcher。
